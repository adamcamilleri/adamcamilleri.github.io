In script.js, add SoundCloud Widget integration:

1. At the top of the IIFE (near the YouTube player variables around line 60-70), add:
   - var scWidget = null;
   - var scReady = false;
   - var scLoaded = false; // tracks if current song is loaded in SC widget

2. Add initSoundCloudWidget() function (call it from the DOMContentLoaded or init flow):
   - Get iframe by id "scWidget"
   - If iframe and typeof SC !== 'undefined': create scWidget = SC.Widget(iframe)
   - Bind SC.Widget.Events.READY: set scReady = true
   - Bind SC.Widget.Events.ERROR: log warning, set scReady = false (will fallback to YouTube)

3. Modify initAudioForSong(song) to also load SoundCloud:
   - If song.soundcloudUrl AND scWidget AND scReady: call scWidget.load(song.soundcloudUrl, { auto_play: false, show_artwork: false, callback: function() { scLoaded = true; } })
   - Keep existing YouTube cue logic as fallback

4. Modify playClip() to add SoundCloud as PRIMARY audio source (before YouTube):
   - New priority: if song.soundcloudUrl AND scWidget AND scReady AND scLoaded -> play via SoundCloud
   - SoundCloud play path: scWidget.seekTo(0), then scWidget.play(), set state.playing = true, setPlayIcon(true), start ytClipTimer for duration, on timeout: scWidget.pause() + setPlayIcon(false)
   - Existing YouTube path stays as second priority
   - Existing playFallback() stays as last resort

5. Modify stopCurrentClip() to also handle SoundCloud: if scWidget, call scWidget.pause()

6. Call initSoundCloudWidget() in the initialization flow (where ytPlayer is set up, around the onYouTubeIframeAPIReady area or near DOMContentLoaded)

Do NOT remove the YouTube or fallback audio paths. SoundCloud is additive -- the priority chain is SC -> YouTube -> stream proxy. If a song has no soundcloudUrl, it falls through to YouTube. If YouTube fails, it falls through to stream proxy.

Do NOT use new Audio(soundcloudUrl) -- this is CORS-blocked. Only use the iframe widget.

Ensure the SC integration logic is structured so that __tests__/songdle-soundcloud.test.js can validate the key behaviors (seekTo(0) before play, error fallback, load with soundcloudUrl). If the IIFE makes direct testing hard, expose the key functions on a testable namespace (e.g., window.__songdleTest = { playSoundCloud, initSoundCloudWidget }) gated behind a test environment check, or restructure just enough for the tests to hook in.
