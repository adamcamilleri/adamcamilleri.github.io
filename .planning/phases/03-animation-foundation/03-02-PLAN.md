  <action>
Modify index.html with these changes:

1. **Add shared CSS** in the `<head>` section, after the existing style.css link:
   ```html
   <link rel="stylesheet" href="shared/animations.css">
   ```

2. **Add GSAP CDN scripts** at the bottom of `<body>`, BEFORE any module scripts. These must be synchronous (no defer/async) so GSAP is available when animations.js loads (see RESEARCH pitfall 3):
   ```html
   <script src="https://cdn.jsdelivr.net/npm/gsap@3.14.2/dist/gsap.min.js"></script>
   <script src="https://cdn.jsdelivr.net/npm/gsap@3.14.2/dist/ScrollTrigger.min.js"></script>
   ```

3. **Add animation init script** after GSAP scripts:
   ```html
   <script type="module">
     import { initScrollAnimations } from '/shared/animations.js';
     // Wait for hero curtain to finish before starting scroll animations
     // (prevents elements animating behind the curtain -- RESEARCH pitfall 5)
     const curtain = document.getElementById('heroCurtain');
     if (curtain) {
       curtain.addEventListener('transitionend', () => {
         initScrollAnimations({
           sections: '.scroll-reveal-section',
           cards: '.project-card-h'
         });
       }, { once: true });
       // Fallback: if curtain already finished or doesn't animate (e.g., reduced motion)
       setTimeout(() => {
         initScrollAnimations({
           sections: '.scroll-reveal-section',
           cards: '.project-card-h'
         });
       }, 2000);
     } else {
       initScrollAnimations({
         sections: '.scroll-reveal-section',
         cards: '.project-card-h'
       });
     }
   </script>
   ```

4. **Add animation CSS classes to interactive elements:**
   - All `.project-card-h` divs: already exist, will be targeted by staggerCards
   - All `.btn`, `.btn-project-primary`, `.btn-project-ghost`, `.download-cv` elements: add `interactive` class
   - All `.social-icon` links: add `interactive` class
   - All `.project-card-h` cards: add `interactive` class

5. **Add scroll-reveal-section class** to major sections:
   - `#about` section: add `scroll-reveal-section` class
   - `#projects` section: add `scroll-reveal-section` class (it already has `scroll-reveal`)
   - `#contact` section: add `scroll-reveal-section` class
   - Do NOT add to `#home` (hero) -- it has its own curtain animation

6. **Add animated-form class** to the contact form:
   - `#contactForm`: add `animated-form` class

7. **Add nav-link-animated class** to nav links:
   - Each `.nav-links a` element: add `nav-link-animated` class

  <name>Task 2: Update style.css to integrate with shared animation classes</name>
  <files>style.css</files>
  <action>
Update portfolio style.css with targeted additions (do not rewrite existing styles):

1. **Ensure existing hover effects don't conflict with .interactive class.** Review existing hover rules on `.project-card-h:hover`, `.social-icon:hover`, button hovers. If any already set `transform` or `box-shadow` on hover, either:
   - Remove the inline hover transform/shadow and let the `.interactive` class from shared CSS handle it, OR
   - Override `.interactive.project-card-h:hover` with the existing specific transform if it's intentionally different

   The goal: `.interactive` provides consistent baseline hover (translateY -2px + shadow), but project cards can keep their specific hover if it's part of the card design. Use specificity to layer, not fight.

2. **Scroll reveal initial state for GSAP:** Do NOT add opacity:0 or transform in CSS for scroll-reveal-section elements. GSAP sets the initial state via `gsap.from()` -- if CSS also sets it, elements will be invisible with reduced-motion on (RESEARCH pitfall 1). The `.scroll-reveal-section` class should have no animation-related CSS in style.css.

3. **Contact form enhancement:** The `.animated-form` selector in shared/animations.css handles focus rings. In style.css, add validation message containers if not already present:
   ```css
   .form-group .validation-message {
     color: #e53e3e;
     font-size: 0.85rem;
     margin-top: 0.25rem;
   }
   .form-group .validation-message.is-valid {
     color: #38a169;
   }
   ```

4. **Nav link transition integration:** The `.nav-link-animated` styles from shared CSS provide the underline effect. Check if existing `.nav-links a` styles set conflicting `text-decoration` or `::after` pseudo-elements. If so, adjust to not conflict with the `.nav-link-animated::after` underline.

5. **Ensure all transition properties are explicit** -- search for any `transition: all` in style.css and replace with specific property transitions. This prevents unintended animation of properties like width, height, or padding.

Do NOT remove or restructure existing sections of style.css. Only add new rules and make minimal adjustments to prevent conflicts.
