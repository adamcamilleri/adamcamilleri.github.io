Create the `.claude/commands/` directory and write `.claude/commands/tdd.md`.

The file must have this exact frontmatter:
```yaml
---
name: tdd
description: Test-driven workflow. Use when writing new features or fixing bugs.
disable-model-invocation: true
argument-hint: "[feature description or bug description]"
---
```

The body of the command should guide Claude through this workflow when invoked as `/tdd $ARGUMENTS`:

**Structure:**

1. **Classify the work** — Is this a new feature or a bug fix? (Infer from $ARGUMENTS; ask only if truly ambiguous)

2. **If BUG FIX** (matches the CLAUDE.md bug report rule):
   - Step 1 — Write a FAILING test that reproduces the bug described in $ARGUMENTS
   - Step 2 — Run the test suite and confirm the test FAILS (show the failure output)
   - Step 3 — Fix the minimal code necessary to resolve the bug
   - Step 4 — Run the test suite and confirm the test PASSES
   - Rule: Do not modify production code before the failing test exists

3. **If NEW FEATURE**:
   - RED — Write a failing test that describes the desired behavior of $ARGUMENTS
   - Run the test and confirm it FAILS
   - GREEN — Write the minimal production code to make the test pass
   - Run the test and confirm it PASSES
   - REFACTOR — Clean up the implementation (rename, extract helpers, remove duplication)
   - Run the test again to confirm it still PASSES after refactor

4. **Test locations reminder** — note where tests live:
   - Root Jest: `npm test` (files in `__tests__/`)
   - TaskMaster Jest: `cd projects/taskmaster && npm test`
   - Cypress E2E: `npm run test:e2e`

5. **Commit rule** — Only commit after the test suite is green

Keep the command body focused and scannable — use numbered steps and code blocks for commands. Total length: 40-70 lines (body only, not counting frontmatter).
